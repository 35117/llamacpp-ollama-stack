# 海龟汤 · 本地主持人

用本地 llama.cpp 部署当海龟汤（lateral thinking puzzle）的主持人：玩家问是非问题，
主持人答「是 / 不是」，玩家据此逼近真相。

**不需要安装 Jev、imajev 或任何新模型。** 原理见下文「为什么不装 Jev」。

---

## 两种打开方式

### 推荐：从聊天界面进（零额外进程）

先启动底座（双击 `scripts\tray.vbs`，或跑 `scripts\start-all.bat`），然后：

- **聊天界面左下角点「🎲 小游戏」→「🐢 海龟汤」**
- 或直接打开 <http://127.0.0.1:11434/turtle>

海龟汤**已经挂在桥上了**，不需要再单独启动任何服务。
页面加载时会自动预热判题模型（左上角标签显示「准备中…」→「就绪」）。

### 独立运行（调试用 / 给别的程序调用）

```
双击  turtle\start.bat
```
或
```
python turtle\server.py --model qwen3-8b --mode binary
```

脚本会依次：拉起 llama.cpp 底座 → 启动判题服务 → 自动打开
<http://127.0.0.1:11440>。关掉那个黑窗口即停止游戏服务（底座仍在后台）。

> **Docker 里的程序（例如 AstrBot 的机器人插件）现在走的是桥上的 `/turtle`**，
> 不需要这个独立服务、也不需要 `--host 0.0.0.0`：实测容器经
> `host.docker.internal:11434/turtle` 就能直接访问桥，即便桥绑的是
> `127.0.0.1`（Docker Desktop 会把宿主机的回环一并转发给容器）。
> 下面这套独立运行方式保留给本地网页与调试用。

两种方式**共用同一套业务逻辑**（`turtle/game.py`），只是入口不同。

| 参数 | 可选值 | 说明 |
|---|---|---|
| `--model` | `qwen3-8b`（默认）/ `qwen35-4b-heretic` | 判题模型；4B 只要 2.7GB 显存，准确率 93.5% |
| `--hint-model` | 默认 `qwen35-4b-heretic` | 出提示的模型（4B 比 8B 更不容易泄露汤底） |
| `--mode` | `binary`（默认）/ `three` / `four` | 见下面的准确率表 |
| `--host` | 默认 `127.0.0.1` | 要给 Docker 容器调用才需要改成 `0.0.0.0` |
| `--port` | 默认 `11440` | 仅独立运行时有效 |

### 它是怎么挂到聊天界面上的

- `scripts/turtle_web.py` —— `/turtle` 的静态文件与 `/turtle/api/*` 分发
- `scripts/ollama_bridge.py` —— 在 `_is_admin_route` / `_handle_admin` 里加了一条
  分支（`TURTLE_PREFIX = "/turtle"`），与 `/ui`、`/admin/*` 同级
- 判题请求**直接发往 llama-swap 上游（11435）**，不走桥自己，否则会递归调用
- `ui/index.html` —— 左下角「小游戏」菜单（结构是列表，以后加游戏只需加一行 `<a>`）
- `turtle/index.html` —— API 基址按当前路径自适应（`/turtle` 下走 `/turtle/api`，
  独立跑走 `/api`），**同一份页面两边都能用**，不用维护两份

> **改了桥、或任何被桥 import 的模块（`turtle_web.py` / `game.py` / `judge.py`）
> 之后，都必须重启底座**（`scripts\service_ctl.py restart`）才生效。**
> 桥是长驻进程，Python 模块一旦被 import 就驻留在内存里 —— 不重启就还在跑旧代码。
> 两种典型症状（都实际踩过）：
> - **新增路由没生效** → `/turtle` 被透传给 llama-swap，返回一个 Go 味的
>   `404 page not found`（而不是桥自己的 JSON 错误）
> - **改过的接口返回旧结构** → 例如 `guess` 不返回 `score` 字段、而是 `None`

## 实测判题准确率

75 条人工标注的探针（5 道经典题 × 15 问），答案只能取「是 / 否 / 无关 / 部分对」。
判题时用 llama.cpp 的 `grammar`(GBNF) 把输出**锁死**在候选标签内，temperature=0。

| 模型 | 模式 | 准确率 | 随机基线 | 热态耗时 |
|---|---|---|---|---|
| **qwen3-8b** | **二分类（是/否）** | **96.8%** (60/62) | 51.3% | ~0.2s |
| qwen35-4b-heretic | 二分类（是/否） | **93.5%** (58/62) | 51.3% | ~0.16s |
| qwen35-4b-heretic | 三分类（+无关） | 80.8% (59/73) | 39.3% | ~0.16s |
| qwen3-8b | 三分类（+无关） | 78.1% (57/73) | 39.3% | ~0.2s |
| qwen3-8b | 四分类（+部分对） | 74.7% (56/75) | 37.3% | ~0.2s |
| qwen35-4b-heretic | 四分类（+部分对） | 66.7% (50/75) | 37.3% | ~0.16s |

> **2026-09-29 晚更新**：给二分类提示词补了 3 个针对「表层关联推断」的 few-shot 示例后，
> 8B 从 93.5% → **96.8%**，4B 从 87.1% → **93.5%**（4B 追平了 8B 的旧水平，
> **用 4B 就能省下 2.5GB 显存**）。实测踩到的两条错误
> （「妹妹恨姐姐吗」答"是"、「男人消失与妹妹有关吗」答"是"）已修复，
> funeral 与 match 两道题现在 100%。
>
> 错误模式很集中：**期望「是」的几乎全对，错的都是「否」被答成「是」**——
> 模型倾向于从常识或前后关联去推断，而正确答案要求它只依据真相里写出来的内容。

复现：

```
python turtle\bench.py --models qwen3-8b,qwen35-4b-heretic --modes binary,three,four
```

报告落在 `turtle/results/bench-<时间戳>.md`（含混淆矩阵与逐条错误）。

### 从数据里得到的几个结论

1. **默认用「二分类 + 8B」**，93.5%。海龟汤里「不是」和「无关」对玩家是同一个意思
   （这条线不通），合并掉反而更准、更快。
2. **「部分对」对小模型是毒药。** 加上这一档，4B 从 87% 掉到 67%——模型大量把「否」
   误判成「部分对」。不是模型笨，四分类的边界对 4B 太细。
3. **8B 只在二元判断上更强。** 三分类时 8B（78.1%）反而不如 4B（80.8%），
   说明「否 vs 无关」的瓶颈是任务定义，加参数解决不了。
4. **决定准确率的是 few-shot 示例，不是 grammar。** 同一套 grammar，
   无示例 53% / 2 个示例 73% / 6 个示例 87%（小样本上）。grammar 的价值是
   保证输出合法、以及把那 0.16s 的速度拿到手。
5. **别开思考。** `enable_thinking=true` 时这套部署会把内容全写进
   `reasoning_content`、`content` 为空；而且 4B 想了 1400 字之后反而更差（27%）。

## 题库：33 题 / 337 条探针，带难度标签

2026-09-30 把题库从 5 题扩到 **33 题**，并给每题加了 `difficulty`：
`easy`（单层反转）/ `medium`（两步因果或一处关键联想）/
`hard`（多层因果、身份或时间线反转、非常识设定、冷门知识）。
分布：easy 9 / medium 15 / hard 9。

### 小模型（4B）实测：**92.3%**，而且与难度无关

用 33 题 337 条探针跑二分类（4B 主测、8B 参照）：

| 模型 | 总体 | easy | medium | hard |
|---|---|---|---|---|
| **qwen35-4b-heretic**（2.7GB） | **92.3%** (299/324) | 92.6% | 91.3% | **93.7%** |
| qwen3-8b（5.2GB） | 95.1% (308/324) | 95.8% | 96.0% | 92.4% |

**最反直觉的一条：难度标签预测不了小模型的判题表现。** 本以为难题会拖垮 4B，
结果 hard 档反而最高。原因不难理解——**判题不是解谜**：判题只需把提问和
`汤底` 对照，而「这题难不难」说的是玩家能不能从 `汤面` 反推出 `汤底`，
两件事用的是完全不同的能力。所以**默认判题不按难度换模型**。

### 真正的短板在「否」题

按期望答案拆开看，4B 的偏置非常干净：

| 4B | 期望「是」 | 期望「否」 |
|---|---|---|
| easy | 98.2% (54/55) | **85.0%** (34/40) |
| medium | **100%** (99/99) | **74.5%** (38/51) |
| hard | **100%** (54/54) | **80.0%** (20/25) |

> 真相里写出来的事它几乎不会答错；错的是把「真相里根本没写的事」答成「是」。
> 这是 4B 的**肯定偏置**，与题目难度没有稳定关系。

### 什么时候值得上 8B

换 8B 整体 **+2.8 个百分点**，收益集中在少数「否定型」题
（`hands` +22%、`windowcleaner` +20%、`pumpkin` +20%、`beggar` +18%）；
反过来也有 5 道题 4B 更好（`phone`、`tunnel`、`owncall`、`circus`、`stamp`）。

- **省显存 / 要快**：全用 4B（2.7GB，热态 ~0.2s）。
- **要最稳**：`python turtle\server.py --model qwen3-8b`。
- **按题路由**：每题都带 `small_model_ok`（实测是否达标）。33 题里 26 题达标，
  低于 0.85 的 7 题是 `beggar` / `seagrass` / `windowcleaner` / `hillcabin` /
  `princess` / `pumpkin` / `hands`。
  ⚠️ 每题只有约 10 条探针，**单题达标与否有噪声**，别当硬结论。

### 探针是自动生成的，但必须人工过一遍

新题只写 `汤面` + `汤底`，探针交给 `gen_probes.py` 生成。**但自动标注有错**：
第一轮跑完，把「4B 与 8B 同时答错」的 24 条拿出来看，大部分不是模型错，
而是**标注写反了**：

```
公主杀了王子？                    标了「否」—— 汤面明写公主杀了他
炸弹是寄给仇人的吗？               标了「否」—— 汤底明写「收件人是他的仇人」
柠檬和龙虾一起食用会导致中毒吗？     标了「否」—— 这正是汤底的核心
```

改正 15 条、删掉 20 条歧义题之后，4B 从 82.6% → **92.3%**，8B 从 89.2% → 95.1%。
**清理前那个「难度梯度」（86.6 / 82.8 / 77.8）几乎全是标注错误的产物**——
错得最多的恰恰是难题的探针。所以别拿自动标注直接当结论。

判据：**两个模型都答错的条目，优先怀疑标注，而不是模型。**

## 模型怎么选（2026-10-02 本机模型换代后重测）

本机模型换过一轮：原来的 `qwen3-8b` / `deepseek-r1-8b` 权重已删，
现在能当主持人的只有三个（`turtle/models.json` 里登记的就是它们）：

| 模型 | 权重 | 判题（337 探针） | 打分 MAE（36 例） | 泄露把关（20 条校准） |
|---|---|---|---|---|
| **qwen35-4b-heretic** | 2.71GB | 92.3% | **4.9** | **100%** |
| qwen35-9b-heretic | 5.63GB | 93.2% | 6.5 | 95% |
| qwen35-9b-abliterated-vision | 5.63GB | 93.2% | — | 67% |

### 判题：大模型没赢

`+0.9` 个百分点看着像提升，但**配对显著性检验说这是噪声**：

| 对比 | 前者独对 | 后者独对 | McNemar p |
|---|---|---|---|
| 4B vs 9B-heretic | 11 | 14 | 0.690 |
| 4B vs 9B-vision | 13 | 16 | 0.711 |
| 9B-heretic vs 9B-vision | 7 | 7 | **1.000** |

三个模型判题能力**统计上无法区分**。而代价是实打实的：显存 2.71GB → 5.63GB
（8G 卡上余量从 ~3.5GB 掉到 **0.4GB**），热态 163ms → 208ms。

**所以判题默认仍是 4B。**「更大 = 更准」在这个任务上不成立 ——
判题只是把提问和汤底对照，不是推理题；难度标签也一样预测不了它（见上文）。

### 打分与把关：4B 也更好

- **打分**（36 例人工期望分）：4B MAE 4.9、9B-heretic 6.5。
  ⚠️ 扩样本前是反过来的（20 例时 4B 4.2 / 9B 2.5）—— 典型的小样本假象，
  **别用 20 条数据下结论**。
- **泄露把关**（20 条人工标注：10 条泄露 / 10 条安全）：4B **100% 准确**（0 错杀 0 漏检），
  9B-heretic 95%，9B-abliterated **只有 67% 精确率** —— 它会把
  「他在这座山上住了多久了？」这类与谜底无关的提问判成泄露。
  这直接解释了提示功能的表现：**把关太严 → 一直重试 → 最后只能给兜底话术**。

### 提示：换大模型不是变好，是把功能废掉

8 道题实测（生成 + 四层保险）：

| 模型 | 终态泄露 | 兜底率 | 平均尝试 | 实际交付的有用提示 |
|---|---|---|---|---|
| **qwen35-4b-heretic** | 4/8 | 3/8 | 2.12 | **5 条**（且被最准的把关判为 0 泄露） |
| qwen35-9b-heretic | 0/8 | 7/8 | 2.75 | 1 条 |
| qwen35-9b-abliterated-vision | 0/8 | **8/8** | 3.00 | **0 条** |

9B 的「0 泄露」是**靠永远兜底换来的** —— 玩家每次点提示都拿到同一句通用话术，
功能等于没有。所以提示也用 4B。

### 结论：三个角色都用 qwen35-4b-heretic

写在 `turtle/models.json` 的 `role_defaults`，界面里点「⚙ 模型」可以随时改。

> **附带发现**：本机 16 个人格里 12 个的底座已被改到 `qwen35-9b-heretic`（正常），
> 但 `at-translate` / `deepseek-r1-8b` / `deletag` / `ds-r1-heretic-zh` 仍指向
> **已删除的底座，目前不可用** —— 到聊天界面的「人格管理」里给它们换个底座即可。

## 换成云端大模型要花多少钱

实测（真实 API usage，不是估算）：

| 操作 | 输入 token | 输出 token |
|---|---|---|
| 判题一次 | 406 | 2 |
| 生成提示一次 | 238 | 12 |
| 语义把关一次 | 174 | 2 |

一局按「问 20 次 + 用 2 次提示」算 ≈ **9,000 token**。

最便宜的可用档是 DeepSeek V4.1-Flash（官方价，非高峰时段）：
输入 $0.15 / 百万（**缓存命中 $0.003**）、输出 $0.6 / 百万。

| 场景 | 每局 | 1000 局 |
|---|---|---|
| V4.1-Flash，**不计缓存**（最保守） | ≈ ¥0.010 | ≈ ¥10 |
| V4.1-Flash，按实际缓存命中 | ≈ **¥0.0015** | ≈ **¥1.5** |
| V4-Pro（更强，不计缓存） | ≈ ¥0.043 | ≈ ¥43 |

**为什么这么便宜** —— 是三个设计选择带来的：

1. **判题不带对话历史。** 每次只发「汤面 + 汤底 + 当前问题」（406 token），
   而不是把整局对话都发过去。若按常规聊天机器人的做法累积历史，
   第 20 轮会涨到 20 倍以上。
2. **输出只有 1 个词。** grammar 把输出锁死成标签，输出 2 token。
3. **prompt 高度重复。** system 与汤底固定不变，缓存命中率 > 90%，
   而缓存命中价只有未命中的 2%。

> 价格取自 DeepSeek 官方文档（2026-09 查），汇率按 1 USD ≈ 7.1 CNY 折算。
> 别家（GPT-5.6 Luna 等）贵 5~20 倍，但结论不变：**个人玩，一局都是分级成本。**

## 提示功能（卡住时引导玩家）

界面上有个「给点提示（剩 N 次）」按钮，**每题最多 3 次**。点一下，主持人会根据
你**已经问过的问题**，给一个引导性的问题，你可以直接拿去问。

### 为什么提示比判题难得多

判题是**有界决策**——grammar 把输出锁死，模型不可能答出格。
提示是**生成任务**，没有 grammar 兜底，小模型最致命的失败是**直接把汤底说出来**，
那游戏当场就结束了。所以先量化了「硬泄露率」（提示里出现汤底核心机关）：

| 方案 | qwen35-4b | qwen3-8b |
|---|---|---|
| 自由生成提示 | 1/5 | 1/5 |
| 只输出「可直接拿去问的问题」 | 1/5 | **3/5** |
| 引导问题 + 关键词自检重试 | **0/5** | 2/5 |

三个反直觉的结论：

1. **8B 比 4B 更容易泄露。** 它把「给个有用的提示」排在了「别泄露」前面，
   会直接输出 `这个男人要水是为了止住打嗝，而不是解渴。`
2. **要求「输出可以直接拿去问的问题」反而让 8B 更糟**（3/5，把答案当问题问了）。
3. **8B 重试 3 次仍会泄露**（`牌子上的字是用什么方式写的？`），
   说明单靠重试不够，**必须有兜底**。

### 实际方案：四层保险

```
0. 玩家一个都没问   →  直接给起步引导，不调模型
1. 模型生成引导性问题
2. 语义把关：用 grammar 有界决策判断「这句话有没有说破谜底」（抓同义改写）
3. 关键词表：题库 leak_words 做廉价预筛
4. 重试用完仍不合格 →  降级为通用兜底提示（不含任何题目专属信息）
```

**为什么必须有第 2 层（语义把关）**：关键词表实测 **0/10 检出**，等于没有。
真实撞到的例子——提示输出了

> `妹妹杀死姐姐是为了让他再次出现？`

而词表里只有「再见到 / 想再见 / 再见他」，**「再次出现」直接漏网**。
手写词表天生追不上同义改写，只能当预筛。

换成语义把往后（同一批 10 条冷启动提示）：

| 检测方式 | 判为泄露 |
|---|---|
| 关键词表 | 0/10 |
| 语义把关（4B） | **6/10**（基本判对） |
| 语义把关（8B） | 1/10（太宽松，漏检） |

**又是「小模型把关更严格」**——所以生成和把关都用 4B。

**冷启动为什么要单独处理**：玩家一个都没问时，模型没有「玩家探索到哪」可依据，
会直接围着谜底核心发问，10 条里有 3 条几乎等于说出答案
（如 `是有人故意让他死在沙漠中央吗？`）。这个场景干脆不调模型。

### 修复后实测

5 题 × 3 次 = 15 条（玩家已问 2 个问题）：

| 指标 | 结果 |
|---|---|
| **最终泄露（关键词命中）** | **0/15** |
| 触发重试 | 10/15 |
| 累计拦下不合格 | 18 条 |
| 降级为兜底 | 2/15 |

把关偏严（宁可错杀），代价是重试和兜底变多——对「防泄露」这个目标是对的。

> 样本只有 5 道题，是**方向性**结论。另外 `beggar` 那道题特别容易降级兜底：
> 它的汤底内容几乎全部浓缩在「牌子上写了什么」，任何围绕牌子的引导都接近答案。
> 这类题应视为「提示难度高」，题库扩容时要留意。

## 猜测打分（猜答案时给百分比）

玩家写下完整猜测后，给一个**百分比 + 等级**：

```
我的猜测
  妹妹因为想让那个男人再出现，所以杀了姐姐。
  75%   大部分正确
  说中了 3 / 4 个要点 —— 具体差在哪，揭晓后可以看到
```

**猜完不列出「差哪几条」。** 检查点就是汤底的拆解，猜一半就把剩下的念出来
等于直接剧透（这个坑实际踩过：玩家猜对一半，系统把「再办一场葬礼」
「男人是葬礼宾客」全说了，游戏当场结束）。所以接口层面就不返回那些内容 ——
不是前端藏起来而已。

> 机器人插件（AstrBot 的 `/answer`）同样遵守这条：只有玩家把**每一条**
> 要点都提到了才判定答对、才公布汤底；差一点时只报准确度，不提缺哪几条。

点「揭晓汤底」之后，才连同汤底一起公布全部要点：

```
汤底（真相）
  妹妹认为那个男人是来参加葬礼的宾客。她想：如果再办一场葬礼，那个男人
  也许还会出现。于是她杀死了姐姐，制造了又一场葬礼。
真相要点
  · 妹妹杀死了姐姐
  · 她的动机跟那个男人有关 —— 想再见到他
  · 她认为那个男人是来参加葬礼的宾客
  · 她想到「再办一场葬礼，那个男人也许就会再出现」
```

满分 100% 会自动揭晓。

### 百分比是怎么来的（这里有个坑）

**不是让模型估计的。** 三种做法实测对比（葬礼题 + 5 个不同接近度的猜测）：

| 猜测（人工期望） | A 让模型直接给 0-100 | B 让模型选分级再映射 | **C 检查点法（采用）** |
|---|---|---|---|
| 完整说中（100） | 100 / 95 | 100 / 80 | **100 / 100** |
| 部分正确（60） | 100 / 80 | 100 / 80 | **75 / 100** |
| 机制说错（40） | 85 / 70 | 80 / 50 | **50 / 50** |
| 动机错（0） | 50 / 40 | 50 / 50 | **25 / 25** |
| 完全无关（0） | **50** / 0 | 50 / 25 | **0 / 0** |

（每格是 4B / 8B 的结果）

- **A 最差**：4B 把「妹妹想继承遗产」这种**完全无关**的猜测打成了 **50 分**。
  小模型的数值估计校准极差 —— 同类实测中裸 Qwen3 4B 的校准分只有 29.1。
- **B 也不行**：同样把无关猜测打成 50 分，实际只有两档有区分度。
- **C 采用**：把真相拆成 3–4 条**关键要素**，逐条问「玩家的话里有没有体现这条？」
  —— 二值判断，正是判题用的那套机制 —— **命中率就是分数**。
  4B 给出 `100 / 75 / 50 / 25 / 0` 的**完美单调**序列。

**分数是算出来的，不是模型估出来的** —— 可复现、不剧透，还能在揭晓时
精确告诉玩家漏了哪一条。（打分用 4B：实测它的分数比 8B 更单调准确。）

## 为什么不装 Jev

「Jev 兼容框架 + llm-qwen3.5-4b」「imajev-4b 压过 Jev」这类说法的核实结果：

- **Jev / JevBench / imajev-4b 都真实存在**，但 **Jev 是 typed decision model
  （类型化决策模型）**：输入「结构化 state + 有界选项」，输出「选项 + 概率」，
  **不生成文本、不做对话**。JevBench 的题目是「这条消息是什么意图」这类英文分类题，
  **不是海龟汤**。它只能覆盖主持人四件事里的「判题」一件。
- **它们全是英文的**（imajev README 明确写 English only），中文海龟汤直接卡在理解环节。
- **8GB 装不下**：imajev-4b 是 Qwen3.5-4B + LoRA，**要下 9.3GB 权重、无官方量化**；
  decider-4b / lev / Tev1 同为「about 8 GB of 16-bit weights」。
- **「80.5% 准确率」查无此数**：真实的数字是 imajev-4b 的 DecisionBench Reasoning
  80.58 和 sealed accuracy 83.3%——是**别的模型、别的子项**，被安到了 local-jev 头上。
- **生态混沌**：JevBench 自称 work in progress，作者说「1 分差距可能是噪音」；
  至少 4 个不相关项目叫 OpenJev、2 个模型叫 lev。中文搜索里那批「Ollama 怎么添加
  Jev 模型」的文章是 AI 生成的幻觉内容（教你去搜 `huihui-ai/jev`，不存在）。

**Jev 真正值钱的那层壳是「有界输出 + 概率」，而 llama.cpp 的 `--grammar` 原生就有。**
你本地已经有 Qwen3.5-4B（和 Jev 派系同源），缺的只是这层壳——所以直接用 grammar，
省掉一整套新部署。

## 题库怎么加

**最省事的路径：只写 `surface` + `bottom`，其余交给脚本。**

```json
{
  "id": "my-puzzle",
  "title": "标题",
  "difficulty": "easy | medium | hard",
  "surface": "汤面（讲现象，不给原因）",
  "bottom": "汤底（真相）",
  "probes": [],
  "checkpoints": []
}
```

然后跑一遍流水线：

```
python turtle\gen_probes.py --dry-run       # 生成探针，先看质量
python turtle\gen_probes.py                 # 只补缺失的题
python turtle\gen_checkpoints.py            # 生成「真相要点」（猜测打分用）
python turtle\bench.py --models qwen35-4b-heretic,qwen3-8b --modes binary --quiet
python turtle\apply_model_tiers.py          # 把实测写回 small_model_ok / model_tiers
```

字段说明：

- `difficulty` —— **人工判定**，描述「这题对玩家有多难」，用于内容挑选。
  ⚠️ 实测它与「小模型判题准确率」**不相关**（见上文），别拿它当判题选型的依据。
- `probes` —— `bench.py` 用的标注。`a` 只能取 `是 / 否 / 无关 / 部分对`；
  `why` 写明依据；`source: "auto"` 表示自动生成、未逐条审校；
  `hard: true` 表示该标注带主观性，统计时单列。
- `checkpoints` —— 玩家猜答案时逐条二值判断的关键要素，命中率即分数。
- `leak_words` —— 提示功能的**廉价预筛**，可不写（真正的把关是语义级的
  `judge.check_leak()`）。
- `small_model_ok` / `measured` —— 由 `apply_model_tiers.py` 依据实测写入，**别手改**。

### ⚠️ 自动生成的探针必须人工过一遍

`gen_probes.py` 的标注**确实会错**（第一轮实测：15 条写反、20 条歧义）。固定流程：

1. 跑完 bench，把「4B 与 8B **同时**答错」的条目挑出来；
2. **优先怀疑标注，而不是模型** —— 大部分确实是标注写反了；
3. 改正写反的、删掉歧义太大的，再重跑 bench。

> 实测这一轮清理把 4B 从 82.6% 拉到 92.3%。**不清理的准确率是假的。**

### 加题后**不用**重启

`turtle_web.get_game()` 会检查题库文件的 mtime，变了就重建 `Game` ——
改完 JSON 立刻生效，不必中断模型服务。
（独立版 `server.py` 是启动时构造一次，仍要重启才生效。）

> 重建会顺带重置提示计数（`_hint_counts` 挂在 `Game` 上），可以接受。
> AstrBot 那边每次开局都会重新拉清单，所以新题马上就能玩到。

## 给外部调用方（机器人插件）用的接口

判题默认**按难度自动选模型**（`model_tiers`）；调用方也可以自己读难度决定。

| 接口 | 说明 |
|---|---|
| `GET /turtle/api/config` | 运行配置。含 `model_desc`、`auto_model`、`model_tiers`、`roles`、`effective`、`models` |
| `GET /turtle/api/puzzles` | **题库清单**：每题 `id / title / difficulty / recommended_model / small_model_ok / probe_count`，另有 `difficulty_counts` 与 `model_tiers` |
| `GET /turtle/api/models` | **可选模型清单** + 三个角色当前各用谁（`roles` / `effective`），以及每个模型的评测说明 |
| `POST /turtle/api/settings` | **切换模型**：`{"judge_model": "<id 或 auto>", "hint_model": ..., "grade_model": ...}`，可只给其中一个 |
| `POST /turtle/api/new` | 出题。返回里新增 `difficulty` 与本次将使用的 `model` |
| `POST /turtle/api/ask` | 判题。可传 `model` 临时指定（优先级高于设置） |
| `POST /turtle/api/guess` | 打分。可传 `model` |
| `POST /turtle/api/hint` | 提示。可传 `model` |
| `POST /turtle/api/guess` | 给完整猜测打分，返回 `score / hit / total / level / graded`。**不返回检查点内容**（猜一半就知道差哪几条＝剧透） |

```json
// GET /turtle/api/puzzles 的片段
{
  "count": 33,
  "difficulty_order": ["easy", "medium", "hard"],
  "difficulty_counts": {"easy": 9, "medium": 15, "hard": 9},
  "auto_model": true,
  "model_tiers": {
    "easy":   {"model": "qwen35-4b-heretic", "small_accuracy": 0.926, "..." : "..."},
    "medium": {"model": "qwen35-4b-heretic", "small_accuracy": 0.913, "..." : "..."},
    "hard":   {"model": "qwen35-4b-heretic", "small_accuracy": 0.937, "..." : "..."}
  },
  "puzzles": [
    {"id": "hiccup", "title": "酒吧里的枪", "difficulty": "easy",
     "recommended_model": "qwen35-4b-heretic", "small_model_ok": true}
  ]
}
```

- **想换模型**：起服务时加 `--model qwen3-8b`，整局都用它、忽略分级。
- **想按题路由**：读 `small_model_ok`（实测是否达标），比按 `difficulty` 靠谱。
- 另有一份人工结论在题库顶层 `judge_recommendation`（含「否题短板」等实测数字）。

## 已知局限

- **准确率不是 100%**：小模型（4B）全库 92.3%、大模型（8B）95.1%。
  短板集中在「否」题（4B 只有 74.5%~85%）：真相里没写的事，它倾向于答「是」。
- **题库仍偏小，且探针质量参差**：33 题 / 337 条探针，其中约 1/5 是人工审校的
  （5 道经典题），其余来自 `gen_probes.py` 自动生成、只做过一轮针对性清理
  （改正 15 条、删除 20 条）。**每题样本仅约 10 条，单题数字有噪声。**
- **难度标签不预测判题难度**：实测三个档位的小模型准确率几乎持平
  （92.6 / 91.3 / 93.7）。它是给「挑题」用的，不是给「挑模型」用的。
- **8B 不是到处都更好**：5 道题上 4B 反而更准（`phone`/`tunnel`/`owncall`/
  `circus`/`stamp`），说明这活儿不完全吃参数量。
- **首次提问会等十几秒**：那是模型冷加载进显存。默认只预热 4B；
  选到 hard 题（判题要 8B）时首次会再等一次。
- **显存**：4B 约 2.7GB、8B 约 5.2GB。桌面程序占多了导致加载失败时，
  用 `--model qwen35-4b-heretic` 兜底。
